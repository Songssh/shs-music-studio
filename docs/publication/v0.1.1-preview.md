# SHS Music Studio v0.1.1 Preview

SHS Music Studio is an independent modification of [HOT-Step CPP v1.4.2](https://github.com/scragnog/HOT-Step-CPP). Original project and dependency copyright notices are retained. It combines local AI music generation with a multi-user production workspace and a shared server GPU.

## Source changes

- Existing ACE-Step, MiniMax-Music3 and YuE2 generation, Cover/Repaint, Lyric, Training, Stem, MIDI and library tools remain available.
- Windows Floating/Docking Workspace with per-user taskbar, layout and background; account hub and integrated private/shared image library.
- Window groups minimize, maximize, close and restore together. Floating windows may move partly outside the workspace.
- Seven Snap layouts: equal columns, wide left, wide right, thirds, quarters, large window with two side windows, and rows.
- Snap Assist, top Snap Bar handle, zero outer/inter-window gaps, shared-boundary resizing and saved arrangement restoration.
- Engine selection remains usable from modal launchers and the sidebar.
- Better Auth accounts, ownership checks and common GPU scheduling are preserved. Android continues to use the existing mobile browser UI.

## Portable installation and LAN access

The new Portable is a **draft review candidate** until the redistribution and provenance gates in [BINARY-REDISTRIBUTION.md](BINARY-REDISTRIBUTION.md) are resolved. Do not treat the older v0.1.0 asset as this version.

After a cleared package is published, compare its SHA-256 with SHA256SUMS.txt, extract the whole ZIP to a writable Windows x64 folder, and run Setup.bat. Choose a separate data folder. Run SHS-Music-Studio.bat or HOT-Step.bat and create the initial administrator using the one-time token at `<data>/library/auth-private/bootstrap-token`. No default password is distributed. Obtain model weights separately under their respective terms. An appropriate NVIDIA driver is required for CUDA.

Default `https://localhost:3443` binds to loopback. For another PC or Android device on the same LAN, stop the server, run `Configure-LAN.bat -Address <server-private-IPv4>`, then restart. The helper updates the listener to `0.0.0.0`, the canonical HTTPS origin and the certificate IP SAN together. Use that exact HTTPS address on every client. Verify and trust only the public `server.crt`; never distribute PFX/private keys or backup folders. If needed, apply the helper's displayed firewall command for the configured Node executable, Private profile and LocalSubnet. The internal engine stays on `127.0.0.1`; do not expose its port. There is no automatic firewall or router port-forwarding change.

PEM certificates and a loopback HTTPS reverse-proxy arrangement are supported by explicit setup options described in README.md; the LAN helper only handles self-signed private IPv4. Internet deployment and access from a second physical device have not been certified by these local checks.

## Verification and limits

Server typecheck, UI TypeScript/Vite production build, server bundle, 40 focused authentication/ownership/image/layout/Snap tests and eight disposable Windows LAN helper tests pass. 32 Snap browser checks and 19 window-group browser checks pass in isolated Edge harnesses. Packaged-runtime checks are recorded in the publication report; tests not executed are not implied to pass. Vite reports a large main chunk.

This is a preview. A clean Windows PC, physical Android, every GPU/driver, external security review and all music-generation/training paths remain outside the verified scope. Models and user databases/music/images/certificates are excluded. Preserve and back up the separate data directory when upgrading. RVC and HeartMuLa are **not implemented**; no delivery date is promised.

The manifest identifies the exact public commit/tree used for the fresh server and UI. Existing C++/third-party runtimes are individually hashed and explicitly marked as not rebuilt, with unverified corresponding-source provenance. This limitation blocks public binary publication.
